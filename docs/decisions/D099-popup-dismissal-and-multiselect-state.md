## 2026-11-09 — D99: preserve popup state through scroll and multi-select picks

- Context: shared `@rivinia/popup` treated every page scroll as an outside dismissal. On mobile this includes scroll gestures that begin outside the panel; searchable multi-select also closed and reopened after each pointer pick, clearing the query and moving focus. D86 captured the earlier behavior and its conformance requirements.
- Decision: mouse and pen presses outside dismiss immediately. A short outside touch tap dismisses after pointer-up; touch movement beyond the tap threshold cancels dismissal. Page scroll repositions an open popup while its trigger remains in the visual viewport and dismisses it after the trigger leaves that viewport. Scrolling inside the panel does not dismiss it. Height-only resize repositions; viewport width changes dismiss.
- Select multi mode stays open on pointer and keyboard picks. Searchable multi pointer picks retain the query and filter focus; they do not change the active row as a side effect of toggling a different option. Single-select still closes on pick. Menu's pick behavior is unchanged.
- Implementation: `bindPopupDismissal` accepts host reposition and trigger-rect callbacks. Both Select and Menu supply them. Select's internal popup component uses a `closeOnPick` switch, defaulting to `true`, wired from the actual controller mode; it is not a consumer API and no package exports change. Legacy callers without reposition/trigger callbacks keep their prior synchronous scroll-close behavior.
- Evidence: popup unit tests cover mouse/pen, touch tap/drag/cancel, scroll visibility, resize, cleanup and SSR. Browser conformance covers shared behavior; select E2E covers multi keyboard and searchable pointer state. Real-device iOS/Android and assistive-technology checks remain required and are listed in `docs/releases/1.0/HUMAN-CHECKS.md`.
- D86 remains immutable historical evidence and is superseded only for the scroll, touch, resize and multi-pick policies above. Its shared conformance and cleanup requirements remain.
- Release: no package version, tag, PR, or publication is part of this change. If accepted for release, this runtime behavior change requires a synchronized minor release across all eleven packages under the current release-group policy; the `Unreleased` changelog notes are proposals, not published claims.
